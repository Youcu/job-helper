# 코드 규약

## 이름

**무엇인지 말하는 이름을 쓴다.** 자리만 채우는 이름은 다음 사람이 코드를 열어 보게 만든다.

| 나쁨 | 좋음 | 왜 |
|---|---|---|
| `vocab.py` | `filters.py` · `skills.py` | "어휘" 는 두 가지를 다 덮어 아무것도 말하지 않았다 |
| `_load()` | `_load_tag_file()` | 무엇을 읽는지 |
| `KEY` | `KEY_COLUMN` | 무엇의 키인지 |
| `BASE` | `BASE_URL` | base 가 무엇인지 |
| `collect_list()` | `fetch_listings()` | `list` 가 내장과 겹치고 `collect.collect_list` 는 말이 겹친다 |

**같은 이름으로 다른 것을 가리키지 않는다.** `_corpus()` 가 두 모듈에서 서로 다른 것을
뜻하고 있었다. `_skill_corpus()` 와 `dictionaries.corpus()` 로 갈랐다.

**모듈 이름과 함수 이름이 겹치지 않게 한다.** `collect.collect_list` 가 아니라
`collect.fetch_listings`.

## 모듈

**한 모듈은 한 가지 일을 한다.** 판단 기준은 크기가 아니라 **같이 바뀌는가**다.

- `vocab.py` 227줄 — "직군·직무·근무지 코드 매핑" 과 "기술 이름 찾기" 는 같이 바뀔 이유가 없다 → 갈랐다
- `store.py` 176줄 — "CSV 저장" 과 "실행 락" 은 무관하다 → 갈랐다
- `record.py` 107줄 — 표기 함수들이 함께 있어야 읽힌다 → 그대로 뒀다
- `collect.py` 118줄 — 페이지네이션과 상세 수집은 같은 "가져오기" 관심사다 → 그대로 뒀다

**줄 수로 나누지 마라.** 나눌 축이 없는데 크기 때문에 나누면 읽기만 어려워진다.

## import

**라이브러리는 `sys.path` 를 건드리지 않는다.** import 만 해도 경로가 바뀌면 어디서 무엇이
깨질지 예측이 안 된다. 경로 설정은 **엔트리포인트와 테스트 러너에서만** 한다.

```python
# wanted.py — 여기서만
ROOT_DIR = Path(__file__).resolve().parent
sys.path.insert(0, str(ROOT_DIR.parent))

# lib/*.py — 그냥 import 한다
from _common.normalize import canonical
```

`_common/` 은 어느 사이트도 import 하지 않는다.

## 실패

### 조용히 실패하지 않는다

멈췄으면 **왜 멈췄는지** 찍는다. 안 보이면 유실을 알아챌 수 없다.

```
목록 수집 종료 사유
  518(개발): links.next 없음 (offset=100, 마지막 페이지 21건)
```

건너뛴 것도 센다.

```
기술스택이 하나도 없어 제외: 4건
공고번호가 없어 제외: 0건
30일 넘게 안 보여 뺀 공고: 1건
```

### 한 건 실패로 전체를 접지 않는다

상세 수집 한 건이 타임아웃 나도 나머지는 가져온다. 실패는 모아서 끝에 알린다.

반대로 **중간에 죽으면 앞서 모은 것을 잃는 구조는 만들지 않는다.** 목록 3페이지째가
실패하면 앞 2페이지를 버리는 게 아니라, 멈추되 이유를 남기고 모은 것을 돌려준다.

### 모르는 것을 단정하지 않는다

| 상황 | 하지 않을 것 | 할 것 |
|---|---|---|
| 사전에 없는 기술 이름 | 가까운 것에 억지로 붙인다 | 그대로 둔다 |
| 날짜를 모르는 행 | 오래됐다고 보고 지운다 | 남긴다 |
| 오늘이 언제인지 못 읽음 | 기본값으로 만료 판정 | 판정 자체를 안 한다 |
| 모르는 근무지 이름 | 조용히 버린다 | 크게 알린다(`LocationError`) |

**지우는 판단에 "모르겠으면 지운다" 는 없다.**

### 실패 방향을 고른다

틀릴 수밖에 없다면 **누락되는 쪽**으로 틀린다. 틀린 값이 CSV 에 들어가는 것보다 낫다.

한글 낱말 경계 규칙이 그렇다. `딥러닝모델` 을 거부해 놓칠 수는 있어도,
`가상화폐` 를 `가상화` 로 잡아 틀린 값을 넣지는 않는다.

## 목록 vs 규칙

**관측한 것을 목록으로 적어 막는 방식은 열린 집합일 때 쓰면 안 된다.**

- `가상화폐` `컨테이너선` … 충돌 복합어 → **열린 집합.** 끝이 없다. 실제로 그 목록은 공고
  600건에서 한 건도 걸러내지 못했다 — 적어 둔 낱말이 그 표본에 안 나왔기 때문이다
- 조사·어미·접미사 → **닫힌 부류.** 한국어 문법이 정했고 새 기술이 나와도 안 늘어난다

목록이 맞는 자리도 있다. `tech_blocklist.txt`(무엇이 기술이 아닌가)와
`tech_ko_allowlist.txt`(어느 한글 낱말이 기술어인가)는 규칙으로 만들 수 없는 **판단**이고,
실패 방향도 누락 쪽이라 안전하다.

**구분하는 질문**: 이 목록이 못 덮는 것이 생기면 **틀린 값이 들어가나, 빠지나?**
틀린 값이 들어가면 규칙으로 바꿔야 한다.

## 주석

**무엇을 하는지가 아니라 왜 그렇게 했는지를 적는다.** 코드가 이미 무엇을 하는지 말한다.

```python
# 나쁨
# tag_type_id 로 corpus 를 조회한다
text = corpus.get(tag["tag_type_id"])

# 좋음
# Wanted 가 준 문자열은 그대로 믿지 않는다 — 자기 corpus 표기와 다를 때가 있다
# (실측: GitHub/Github, PyTorch/Pytorch). id 로 corpus 표기를 먼저 얻는다.
text = corpus.get(tag["tag_type_id"])
```

**실측한 숫자를 적는다.** "많다" 가 아니라 "1,000건 중 166건(16.6%)". 나중에 판단을
다시 할 때 근거가 남는다.

**상수에는 그 값인 이유를 적는다.**

```python
MAX_OFFSET = 100_000    # 폭주 방지. 정상 조건이면 근처에도 못 간다.
RETENTION_DAYS = 30     # 내려간 공고를 영영 쌓으면 지원할 수도 없는 것이 섞인다.
UNBOUNDED_YEARS = 100   # API 는 상한 없음을 100 으로 준다 (실측: 5~100, 3~100).
```

## 죽은 코드

**참조 0곳이면 지운다.** 필요해지면 그때 다시 쓴다.
빌드용 스크립트도 마찬가지다 — 최종물에 남으면 클론한 사람이 돌려 보고 실패한다.

## 설정

**`.env` 파일 하나만 읽는다.** `load_dotenv()` 는 값을 `os.environ` 에 심어서,
`.env` 에 줄이 없는 항목이 셸 환경변수에서 조용히 새어 들어온다. `dotenv_values()` 를 쓴다.

조건이 파일에 안 적힌 채로 결과가 달라지면 **재현이 안 된다.**

**`.env` 는 저장소에 넣지 않는다. 예시 파일도 두지 않는다.**

민감 정보를 막으려고 있는 파일이다. 희망 근무지 하나만으로도 어디 사는지 가늠할 수 있고,
앞으로 API 키 같은 것이 들어갈 자리다. `.env.example` 을 두면 항목을 채워 넣다가 실제 값이
따라 들어간다 — 실제로 그렇게 만들었다가 근무지가 그대로 들어간 적이 있다.

**없으면 안 도는 것이 맞다.** 대신 **`README.md` 에 필요한 항목을 적는다.**
클론한 사람은 그걸 보고 직접 만든다.
