# 결정과 근거

규약이 왜 그 모양인지의 기록이다. **근거는 전부 실측이다** — 짐작으로 정한 것은 없다.
나중에 상황이 바뀌면 여기 숫자를 다시 재서 뒤집으면 된다.

---

## D-01 · 사이트는 API 만 쓴다. HTML 은 안 긁는다

**확인한 것** — 공고 페이지의 `__NEXT_DATA__` 와 상세 API 응답을 20건 전수 대조했다.
본문 7필드(`requirements` `preferred_points` `position` `main_tasks` `intro` `benefits`
`hire_rounds`)가 **바이트 단위로 같았다.** 마감일도 20/20 일치.

오히려 API 에만 있는 필드가 더 많았다(`skill_tags` `attraction_tags` `wanted_pick`).
페이지 데이터에는 `skill_tags` 가 **아예 없다.**

**그래서** — API 만 쓴다. 화면 구조가 바뀌어도 흔들리지 않는다.

**새 사이트에서 할 일** — 같은 대조를 먼저 한다. 다르면 무엇이 부족한지 적고 판단한다.

## D-02 · 페이지네이션에서 `limit` 을 동적으로 줄이지 않는다

**확인한 것** — 전체가 정확히 49건인 조건으로 경계를 찔렀다.

| 요청 | 받은 건수 | `links.next` |
|---|---|---|
| `limit=25 offset=25` | 24 | 없음 |
| `limit=49 offset=0` | 49 | **없음** |
| `limit=50 offset=0` | 49 | 없음 |
| `limit=0` / `-1` | 0 | 없음 (HTTP 200) |

`limit` 은 **최대**지 요구 수량이 아니다. 페이지가 딱 꽉 차도 남은 게 없으면 `next` 가 없다.

**그래서** — 줄일 이유가 없다. 오히려 **`limit=0` 이 200 에 빈 배열을 주므로**, 줄이다 0 에
닿으면 "끝" 으로 오해한다.

**대신 막은 것** — 서버가 offset 을 무시해 같은 페이지를 반복하는 경우, 수집 중 공고가
추가·삭제돼 경계가 밀리는 경우, 폭주. 그리고 **종료 사유를 출력**한다.

## D-03 · 기술 이름은 응답의 두 자리에서 모두 뽑아 합친다

**확인한 것** — 기술 이름은 상세 응답 한 벌 안의 두 자리에서 나온다.
① `skill_tags`(회사가 목록에서 골라 체크) ② 산문(`requirements` 등).

122건 실측:

| | |
|---|---|
| ① 을 채운 공고 | 29 / 122 (24%) |
| ① 의 기술 중 ② 에도 나오는 것 | 102 / 183 (56%) |
| **① 에만 있는 기술** | 81개 |
| **① 이 비고 ② 에만 있는 공고** | 87건 |

**어느 한쪽도 다른 쪽을 포함하지 않는다.**

**그래서** — 합친다. 회사가 체크한 것을 앞에, 산문에서 찾은 것을 뒤에.
①②  둘 다 없으면 판단 재료가 없으므로 행을 뺀다.

## D-04 · 표기 정규화는 편집거리로 하지 않는다

**확인한 것** — Reference Project Repo 인 DevSkill 의 `canonicalize()`(rapidfuzz,
threshold 70~85)를 우리 174종에 걸었다.

| 입력 | fuzzy 결과 | 점수 | 등장 |
|---|---|---|---|
| `REST` | **`Rust`** | 75 | 17회 |
| `Apache Kafka` | **`Apache Spark`** | 75 | 10회 |
| `ML` | **`XML`** | 80 | 12회 |
| `MSSQL` | **`MySQL`** | 80 | 3회 |

`Kafka` 가 사전에 있는데도 `Spark` 로 갔다. threshold 85 로 올리면 오매칭은 사라지지만
붙는 것도 2종뿐이다.

**왜 거기서는 되나** — DevSkill 은 **LLM 이 "이건 기술 이름" 이라고 판단해 제안한 소수의
이름**을 스냅한다. 우리는 후보가 많고 기술 약어는 짧고 서로 닮았다.
**같은 함수라도 입력이 다르면 결과가 다르다.**

**그래서** — 명시적 별칭 조회만 쓴다. 사전에 없는 이름은 억지로 붙이지 않고 그대로 둔다.

## D-05 · 공통 corpus 는 씨앗을 병합한 것이지, 갈아탄 것이 아니다

**확인한 것** — DevSkill 온톨로지 271개는 우리가 뽑은 이름의 **등장 기준 67%** 만 덮었다.
못 덮는 것에 `GitHub` `Spring` `REST API` `Google Cloud` `NestJS` `Grafana` `RDBMS` 가 있었다.

**그래서** — 씨앗으로 쓰고 공고 실측 78개를 더해 **349개**로 만들었다.
`kind` 는 DevSkill 의 6종에 `concept`(OOP·TDD·마이크로서비스)과
`protocol`(TCP·HTTP·OAuth)을 더했다 — 채용공고에는 제품이 아닌 것도 기술 요구로 적힌다.

씨앗은 이미 `tech_corpus.json` 안에 합쳐져 있다. **재생성 스크립트는 지웠다** —
개인 절대경로가 박혀 있고 데이터가 이중으로 존재했다. 새 기술은 그 JSON 에 한 항목 더한다.

## D-06 · 한글 낱말 경계는 목록이 아니라 규칙으로 판정한다

**문제** — 한글은 단어경계가 없다. `가상화폐` 안에 `가상화` 가, `컨테이너선` 안에
`컨테이너` 가 들어 있다.

**처음 한 것** — 충돌 복합어를 파일에 적어 막았다. **잘못된 설계였다.**

**확인한 것** — 공고 600건(62만 자)에서:

| | 매치 |
|---|---|
| 아무 판정 없이 | 394회 |
| **제외어 목록** | **394회 — 0건 걸러냄** |
| 조사 규칙 | 394회 |

적어 둔 네 낱말이 그 표본에 **한 번도 안 나왔다.** 117건에서 한 번 본 걸로 만든 목록이었다.

**그래서** — 조사·어미·접미사라는 **닫힌 문법 부류**로 판정한다. 한국어 문법이 정했고
새 기술이 나와도 안 늘어난다.

```
컨테이너를  → 를은 조사   → 통과      컨테이너선 → 선은 셋 다 아님 → 거부
분산 처리한 → 한은 어미   → 통과      가상화폐   → 폐는 셋 다 아님 → 거부
컨테이너화  → 화는 접미사 → 통과
```

형태소 분석기(kiwipiepy)도 재 봤다. 정확도 같고(393회) 공고당 3.2ms 와 C++ 확장 의존성이
늘어 쓰지 않았다.

**일반 원칙** — [04-code-conventions.md](04-code-conventions.md) 의 "목록 vs 규칙".
못 덮는 것이 생겼을 때 **틀린 값이 들어가면 규칙**, **빠지기만 하면 목록**도 된다.

## D-07 · 덮어쓰지 않고 쌓는다. 30일 보존

**확인한 것** — 몇 시간 사이 수집 대상이 122 → 121건이 됐다. 확인해 보니 한 건이
`status=close` 로 마감돼 내려간 것이었다. 덮어쓰기였다면 지원을 준비하던 공고가
흔적 없이 사라진다.

**그래서** — 공고 URL 을 키로 병합한다. 이번에 안 보인 공고도 남기되 **30일 넘으면 뺀다.**
영영 쌓으면 지원할 수도 없는 공고가 지금 열린 것과 섞인다.

**따라온 것** — 쌓는 구조가 되면 파일 하나에 이력이 전부 들어간다. 한 번 깨지면 못 되돌린다.
그래서 **원자적 쓰기**와 **실행 락**을 함께 넣었다.

## D-08 · 설정은 `.env` 파일만 읽는다

**확인한 것** — `load_dotenv()` 는 값을 `os.environ` 에 심는다. `.env` 에 줄이 없는 항목은
셸 환경변수에서 새어 든다. 근무지를 안 적었는데 셸에 `HOME_LOCATIONS=부산` 이 있으면
**부산 공고를 긁는다.**

**그래서** — `dotenv_values()` 로 파일만 읽는다.
조건이 파일에 안 적힌 채 결과가 달라지면 **재현이 안 된다.**

---

## D-09 · 실행 주기는 이 저장소가 정하지 않는다

스크래퍼는 추후 만들 **오케스트레이터 안의 단일 작업**이다. 언제 얼마나 자주 도는지는
그쪽이 정한다.

**여기서 지는 책임은 "몇 번을 돌려도 안전하게" 까지다** — 누적 병합, 30일 보존,
원자적 쓰기, 실행 락.

다만 알아 둘 것: 테스트는 떠 놓은 응답을 쓰므로 사이트가 API 를 바꿔도 통과한다.
**정기 실행이 사실상 유일한 감시 수단**이고, 신호는 실행 시 뜨는 실패 건수와 CSV 빈 칸이다.

---

## D-10 · 사이트에 없는 데이터는 칸을 비우고 사실을 알린다

**확인한 것** — Wanted 상세 응답 60건 전문에서 `salary|annual_income|pay|compensation|wage`
를 검색했다. **0건.** 필드 자체가 없다.

**그래서** — `연봉` 컬럼을 빼지 않고 빈 문자열을 넣는다. CSV 를 합칠 때 모양이 어긋나면
안 된다. `.env` 의 `HOPE_ANNUAL_SALARY` 도 적용하지 않고, 실행이 끝날 때 그 사실을 알린다.

---

## D-11 · `.env` 는 저장소에 넣지 않고 예시 파일도 두지 않는다

**왜** — 민감 정보를 막으려고 있는 파일이다. 희망 근무지 하나만으로도 어디 사는지 가늠할 수
있고, 앞으로 API 키 같은 것이 들어갈 자리다.

**예시 파일을 안 두는 이유** — `.env.example` 을 만들면 항목을 채워 넣다가 실제 값이 따라
들어간다. 실제로 그렇게 만들었다가 근무지가 그대로 들어갔다.

**그래서** — 없으면 안 도는 것이 맞다. 필요한 항목은 사이트 `README.md` 에 적고,
클론한 사람이 직접 만든다.

---

## D-12 · 산출물과 중간 문서는 추적하지 않는다

| | 왜 |
|---|---|
| `<사이트>/csv/` | **사람마다 스크랩 대상이 다르다.** 남의 조건으로 뽑은 CSV 를 받을 이유가 없다 |
| `<사이트>/docs/` | 그 단계를 **만들어 가는 중간 확인용**이다. 보는 대상이 만드는 사람과 에이전트라, 완제품을 쓰는 사람에게는 쓸모가 없다 |

루트 `docs/` 는 추적한다 — 규약은 쓰는 사람에게도 필요하다.

---

## 되돌릴 때

여기 적힌 결정은 **그때의 측정**에 근거한다. 상황이 바뀌면 뒤집어도 된다.
다만 **같은 방식으로 다시 재고**, 이 문서를 고친다. 짐작으로 뒤집지 않는다.
