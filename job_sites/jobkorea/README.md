# 잡코리아 수집기

```bash
../../.venv/bin/python3 jobkorea.py
```

`../../.env` 의 조건으로 공고를 전량 수집해 `csv/jobkorea_post.csv` 를 만든다.
`.env` 는 저장소에 없다 — 민감 정보를 막으려고 있는 파일이라 예시 파일도 두지 않는다.
아래 표를 보고 직접 만들어야 한다.

## `.env` 에 적을 것

| 이름 | 필수 | 뜻 | 예 |
|---|---|---|---|
| `JOB_ROLES` | **예** | 직무. **여섯 사이트가 함께 쓰는 이름**이다 | `백엔드,웹` |
| `YOE` | 아니오 | 년차. 신입=`0`, N년차=`N`, 전체=`-1` | `0` |
| `EDUCATION` | 아니오 | 학력 하나. **지금은 비워 둔다** — 걸면 57건, 빼면 168건 | `대졸4` |
| `HOME_LOCATIONS` | 아니오 | 근무지 이름. 비우면 전국 | `서울,성남시` |
| `EMPLOYMENT_TYPES` | 아니오 | 고용형태. 기본 `regular,intern` | `regular,intern` |
| `TECH_STACKS` | 아니오 | 보유 스택. **아직 거르지 않는다** | `Python,Django` |
| `HOPE_ANNUAL_SALARY` | 아니오 | 희망 연봉. **아직 거르지 않는다** | `3300` |

**직무는 사이트 코드가 아니라 이름으로 적는다.** `.env` 는 여섯 사이트가 함께 쓰는
한 벌이라, `JOB_ROLES=백엔드,웹` 하나를 적으면 이 사이트가 `tags/jobkorea_role_map.json` 로 자기 코드를 찾는다.
쓸 수 있는 이름은 `job_sites/_common/roles.json` 에 있고 별칭도 받는다 — `서버`·`Backend`
라고 적어도 `백엔드` 로 알아듣는다.

**한 이름이 코드 여럿으로 펼쳐진다.** 같은 일을 하는 공고를 사이트가 어떻게 쪼개 뒀든
다 걷는 것이 목적이다. 이 사이트에 없는 직무는 조용히 빠지지 않고 **못 걸었다고 화면에
찍는다** — 조용히 빠지면 왜 결과가 적은지 못 찾는다.

## 이 사이트의 함정

**전부 예외가 안 나고 결과도 나온다.** 그래서 코드가 막는다.

| 함정 | 무슨 일이 나는가 | 어디서 막는가 |
|---|---|---|
| 직무 **대분류** 코드 | `duty=10031` 이 기준선과 같은 197,561건 — **전체가 나온다** | `lib/filters.py` `duty_value` |
| 같은 이름을 여러 번 | **첫 값만** 먹는다. 실측 `jobtype=1&jobtype=3` = `jobtype=1` | `lib/client.py` `_query` |
| 구가 있는 시 | `성남시` 라는 코드가 **아예 없다.** 구로 펼쳐야 한다 | `lib/filters.py` `resolve_locations` |
| 못 옮긴 근무지 | 조용히 빼면 전국을 긁는다 — **결과가 늘어나는 방향** | 같은 곳에서 멈춘다 |
| 페이지 번호 이름 | `page` `pageNo` 는 무시되고 1페이지만 온다. **`Page` 다** | `lib/collect.py` |
| 총계가 목록에 없다 | 따로 물어야 한다. 응답이 `57` 이라는 **숫자 두 글자** | `lib/collect.py` `fetch_total` |

사람인은 반복 파라미터에서 **마지막** 값을 썼다. 방향은 반대지만 결과는 같다 — 조용히 값을 잃는다.

## 엔드포인트

```
POST /Recruit/Home/_GI_List/       목록 조각.  condition[...] + Page=N
POST /Recruit/Home/_SearchCount/   총계.       응답이 숫자뿐이다
GET  /Recruit/GI_Read/{gno}        상세.       JSON-LD 가 여기 있다
GET  /Recruit/GI_Read_Comt_Ifrm    본문.       상세 안에 iframe 으로 들어간다
```

**본문은 상세 페이지에 없다.** 상세 HTML 에는 `iframe` 이라는 글자조차 없어서
(JS 가 나중에 꽂는다) 본문이 아예 없는 줄 알기 쉽다.

## 칸별 적중률 (실측 계약값)

2026-09-06, 조건 = 백엔드·웹개발자 / 신입 / 대졸4 / 서울·경기 5개시 / 정규직·인턴.
사이트 표기 **총계 57건 / 수집 57건 일치**, CSV 55행.

| 칸 | 적중 | 어디서 오는가 |
|---|---|---|
| 기업명 · 마감일 · 경력 · 근무지 · URL | 100% | JSON-LD (`schema.org/JobPosting`) |
| 기술스택 | 100% | 산문 매칭 35행 + 그림 주소 20행 |
| 지원자격 | 67% (글 본문만 보면 **100%**) | 본문 절 나누기 |
| 우대사항 | 56% (글 본문만 보면 **89%**) | 본문 절 나누기 |
| 연봉 | 16% | JSON-LD `baseSalary`. 없는 것이 정상이다 |

**그림 본문이 24%다.** 사람인(18%)보다 나쁘다. 그래서 지원자격·우대사항이 전체로는
낮아 보이는데, 글이 있는 공고만 보면 사람인과 같은 수준이다.

## 기술스택 칸에 `http` 로 시작하는 값이 있다면

**아직 안 읽었다는 표시다.** 본문이 그림인 공고는 여기서 읽지 않는다 (D-13).
읽는 것은 수집이 끝난 뒤 도는 별도 단계(Playwright + Sonnet 병렬)의 일이고,
이 수집기는 "여기는 그림이다, 주소는 이것이다" 까지만 남긴다.

주소를 남기는 조건은 둘이다 — ① 본문이 그림뿐, ② 글은 있는데 기술을 못 찾았다.
편집기가 깔아 주는 템플릿 장식(`i.jobkorea.kr/content/images/...`)은 읽어도 공고
내용이 없으므로 남기지 않는다.
