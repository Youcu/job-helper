# Pathsdog 수집기

```bash
../../.venv/bin/python3 pathsdog.py
```

`../../.env` 의 조건으로 공고를 전량 수집해 `csv/pathsdog_post.csv` 를 만든다.
`.env` 는 저장소에 없다 — 민감 정보를 막으려고 있는 파일이라 예시 파일도 두지 않는다.

## 다섯 사이트 중 유일하게 **공식 인터페이스**를 쓴다

HTML 을 긁거나 비공개 API 를 찾아 헤맬 필요가 없다. `https://jobs.pathsdog.com/mcp` 가
MCP(Model Context Protocol) 서버이고, 도구 두 개로 목록과 상세를 받는다.

```
POST /mcp   JSON-RPC 2.0
  initialize                          첫 인사
  tools/call  search_jobs             목록 (limit/offset)
  tools/call  get_job_detail          상세 (include_full_description=true)
```

인증도 쿠키도 필요 없다. 웹 쪽 `/api/jobs` 는 **401** 이라 오히려 MCP 가 유일한 길이다.

**`Accept` 에 `text/event-stream` 을 넣어야 한다.** 없으면 서버가 406 으로 거절한다
(`Not Acceptable: Client must accept text/event-stream`).

### 응답이 JSON 이 아니라 **글**이다

MCP 는 LLM 이 읽으라고 만든 것이라 라벨 붙은 글을 준다.

```
[ID:2565] ㈜네비웍스 - AI 서비스 백엔드 개발자(신입)
  기술: Backend, AI/ML, Python, React, Docker
  경력: 신입 | 근무지: 대한민국 경기도 안양시 … | 정규직
```

서식이 규칙적이라 파싱은 되지만 JSON 보다 깨지기 쉽다. 그래서 서버가 첫 줄에 말해 주는
`이번 페이지 N개` 와 우리가 읽어 낸 개수를 **매번 대조한다** — 서식이 바뀌면 거기서
드러난다. 글을 파싱하는 이상 이게 유일한 안전망이다.

## 이 사이트의 가치 — 출처가 **기업 자체 페이지**다

신입 + Backend 29건의 원문 출처를 셌다.

| 출처 | 비율 |
|---|---|
| 기업 자체 채용 페이지 (toss.im · careers.nhn.com · careers.nexon.com · greetinghr.com …) | **86%** |
| www.jobkorea.co.kr | 14% |

잡플래닛이 **97%가 잡코리아 중계**라 3%만 쓸 수 있었던 것과 정반대다. 토스·넥슨·NHN·
하이브·업스테이지 같은 기업 직접 공고는 우리가 긁는 다른 사이트에 없다.

## `.env` 에 적을 것

| 이름 | 필수 | 뜻 | 예 |
|---|---|---|---|
| `PATHSDOG_JOB_IDS` | **예** | 역할 **이름**. 숫자 코드가 아니다 | `Backend,Fullstack` |
| `YOE` | 아니오 | 년차. 신입=`0`, N년차=`N`, 전체=`-1` | `0` |
| `HOME_LOCATIONS` | 아니오 | 근무지 이름. 비우면 전국 | `서울,판교` |
| `EMPLOYMENT_TYPES` | 아니오 | 고용형태 | `regular,intern` |
| `EDUCATION` | 아니오 | **여기서는 안 걸린다** (도구에 없음) | `대졸4` |
| `TECH_STACKS` | 아니오 | **일부러 안 건다** | `Python` |
| `HOPE_ANNUAL_SALARY` | 아니오 | 아직 안 쓴다 | `3300` |

**접두사 없는 `JOB_IDS` 로 물러서지 않는다.** 물러서면 남의 사이트 코드로 긁는다.

### 왜 직무가 숫자가 아니라 이름인가

**이 사이트는 직무와 기술을 한 칸에 섞어 쓴다.** MCP 문서가 그렇게 쓰라고 명시한다 —
`"신입 백엔드" → experience_filter: "신입" + skills: ["Backend"]`. 그래서 `skills` 에
`Backend` `Frontend` `iOS` 같은 **역할**을 넣는다.

닫힌 코드표가 아니라 자유로운 이름이라, 코드표에 없는 이름을 적어도 **막지 않는다.**
다만 오타면 결과가 0건이 되므로 화면에 "코드표에 없는 이름" 이라고 알린다.

관측한 역할 이름: `Backend` `Frontend` `Fullstack` `iOS` `Android` `DevOps`
`Data Engineering` `AI/ML` `Machine Learning` `Software Engineering` `QA` `Security`
`Game` `Embedded` `Product Management` `Data Analysis`

### `skills` 는 AND 다

문서가 "입력한 기술을 모두 포함" 이라고 밝힌다. 역할을 여럿 적으면 **둘 다 가진 공고만**
나온다 — `Backend,Fullstack` 은 둘 다인 공고다. OR 로 보려면 나눠 돌려야 한다.

## 서버가 거르는 것과 우리가 거르는 것

| 조건 | 어디서 | 왜 |
|---|---|---|
| 역할 | 서버 `skills` | |
| 경력 | 서버 `experience_filter` | 서버가 정한 구간을 그대로 쓴다 |
| **근무지** | **우리가** | `search_jobs` 에 지역 파라미터가 **없다** (화면에는 있다) |
| **고용형태** | **우리가** | 서버가 **값 하나만** 받아서 `정규직,인턴` 중 하나를 잃는다 |
| 학력 · 기술스택 | 아무도 | 도구에 파라미터가 없다 |

고용형태를 실측했다 — 조건 없이 **29건**, `employment_type=정규직` 으로 **28건**.
한 값만 보내면 인턴 공고를 잃는다. 그래서 안 보내고 상세의 `- 고용형태:` 로 거른다.

경력 구간은 서버가 정한 뜻을 따른다: `인턴` · `신입`(인턴 제외) · `주니어`(**1~3년 + 신입**) ·
`미들`(3~5년) · `시니어`(5년+).

### 근무지 표기가 제각각이다

한 조건 29건에서 서로 다른 표기가 **20가지**였다.

```
서울 · 판교 · 미기재 · 원격 · 제주 · 일본
대한민국 경기도 안양시 동안구 관양동 부림로 170번길 41-18
넛지캠퍼스빌딩                                    ← 건물 이름
NHN Enterprise 광주IDC운영팀을 소개해요 …           ← 파싱이 어긋난 문장
```

이름을 그대로 견주되 `시`·`구` 를 뗀 것도 본다. **근무지가 비면 통과시킨다** — 29건 중
4건이 `미기재` 였고, 잘못 버리는 것보다 넘기는 쪽이 낫다.

## 함정 — `필수 기술`·`우대 기술` 은 기술이 아니다

이름과 달리 **지원자격 문장을 콤마로 자른 것**이다.

```
- 필수 기술: Python 개발 유경험자, Linux 서버 활용 가능자, 형상관리 도구 활용 가능자, …
- 우대 기술: AI관련 개발 유경험자, …, 제출서류, 이력서, 절차안내, 서류전형 > 온라인 테스트, …
                                    ↑ 전형 정보까지 섞인다
```

그래서 지원자격·우대사항은 **원문(`[상세 내용]`)을 절로 갈라** 채우고, 절을 못 찾았을
때만 이 칸으로 물러선다. 진짜 기술 태그는 `- 기술스택:` 쪽이다.

원문을 받으려면 `get_job_detail` 에 **`include_full_description=true`** 를 줘야 한다.
기본으로는 그 절이 빠진다. 표본 8건에서 원문이 8/8 있었고 절 나누기가 8/8 성공했다.

### 원문 앞머리를 떼야 한다

원문이 `공고명: … / 회사: … / 고용형태: …` 로 시작한다. 서버가 정리해 둔 요약이지 공고
내용이 아니다. 절 머리말을 못 찾으면 본문 전체가 지원자격이 되므로(그게 `_common/sections.py`
의 설계다) **이것까지 딸려 들어간다** — 실제로 그랬다.

## 기술스택

①`- 기술스택:` 칸 ∪ ②원문 매칭. **이 칸에는 직무가 섞여 있다**(`Backend`,
`Software Engineering`). 공통 코퍼스로 풀리는 것만 남기면 그 대부분은 저절로 빠지고,
못 푼 것은 `_common/corpus_candidates.json` 으로 쌓여 사람이 본다 (D-14).
