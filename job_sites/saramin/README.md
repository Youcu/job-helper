# 사람인 스크래퍼

    python3 saramin.py

`../../.env` 의 조건으로 공고를 전량 수집해 `csv/saramin_post.csv` 를 만든다.
본문이 그림인 공고는 **읽지 않는다** — 주소만 남겨 나중 단계에 넘긴다.

```
../../.venv/bin/python3 saramin.py       # 실행
../../.venv/bin/python3 tests/run.py     # 테스트 258건
```

## `.env` 항목

`.env` 는 **저장소에 없다.** 민감 정보를 막으려고 있는 파일이라 예시 파일도 두지 않는다
(D-11). 저장소 뿌리에 직접 만든다.

| 항목 | 필수 | 뜻 |
|---|---|---|
| `JOB_ROLES` | **예** | 직무. **여섯 사이트가 함께 쓰는 이름**이다 (`백엔드,웹`) |
| `YOE` | 아니오 | 신입=`0`, N년차=`N`, 전체=`-1` (기본 `-1`) |
| `HOME_LOCATIONS` | 아니오 | 근무지 이름. 비우면 전국 |
| `EMPLOYMENT_TYPES` | 아니오 | `regular` `contract` `intern` `parttime` `freelance` `dispatch` (기본 `regular,intern`) |
| `EDUCATION` | 아니오 | 학력 하나(`대졸4`). **지금은 비워 둔다** — 걸면 143건, 빼면 440건 |
| `TECH_STACKS` | 아니오 | **아직 안 쓴다.** 지금은 거르지 않고 전량 수집한다 |
| `HOPE_ANNUAL_SALARY` | 아니오 | **아직 안 쓴다.** 공고 9%만 실금액을 준다 |

**직무는 사이트 코드가 아니라 이름으로 적는다.** `.env` 는 여섯 사이트가 함께 쓰는
한 벌이라, `JOB_ROLES=백엔드,웹` 하나를 적으면 이 사이트가 `tags/saramin_role_map.json` 로 자기 코드를 찾는다.
쓸 수 있는 이름은 `job_sites/_common/roles.json` 에 있고 별칭도 받는다 — `서버`·`Backend`
라고 적어도 `백엔드` 로 알아듣는다.

**한 이름이 코드 여럿으로 펼쳐진다.** 같은 일을 하는 공고를 사이트가 어떻게 쪼개 뒀든
다 걷는 것이 목적이다. 이 사이트에 없는 직무는 조용히 빠지지 않고 **못 걸었다고 화면에
찍는다** — 조용히 빠지면 왜 결과가 적은지 못 찾는다.

```bash
JOB_ROLES=백엔드,웹
YOE=0
HOME_LOCATIONS=서울,성남시
```

## 경력 · 학력 코드

`tags/saramin_filter.json`. **코드표에 있다고 필터가 먹는 게 아니다** — 실측으로 확인한
함정 셋을 코드가 대신 지킨다.

- `exp_cd=99`(경력무관)는 **필터가 아니다.** 기준선과 같은 수가 나온다. 경력무관은 `exp_none=y`
- `exp_min` `exp_max` 를 단독으로 주면 **통째로 무시된다.** `exp_cd=2` 를 같이 줘야 한다
- `edu_min` 과 `edu_max` 는 **같은 학력에 다른 번호**를 쓴다. 코드 `9` 가 min 에선 석사 이상,
  max 에선 고졸 이하다. 게다가 박사만 순번을 이탈한다(min=5)

| 학력 | `edu_min` | `edu_max` |
|---|---|---|
| 고등학교 졸업 이상 | `6` | `9` |
| 대학졸업(2,3년) 이상 | `7` | `10` |
| 대학교졸업(4년) 이상 | `8` | `11` |
| 석사졸업 이상 | `9` | `12` |
| 박사졸업 이상 | `5` | `13` |

## 사이트 고유의 함정

Wanted 는 UA 하나가 게이트였다. 사람인은 다르다.

| 함정 | 무슨 일이 나는가 |
|---|---|
| 상세를 `jobs/relay/view` 로 받기 | 380KB 짜리 **JS 껍데기**가 온다. 본문 섹션이 통째로 없다. `jobs/view` 를 써라 |
| `class="list_item"` 을 정확히 맞추기 | `list_item effect` 변종을 흘린다. 131건 중 2건을 조용히 잃었다 |
| 1페이지를 그대로 세기 | 위쪽에 광고가 붙는다(광고 13 / 진짜 50). `전체 채용정보` 머리말이 경계다 |
| 마감일을 `deadlines` 에서 읽기 | 그건 "2일 전 등록" 이다. 마감일은 `span.date` |
| 요청 간격 없이 상세 받기 | 0.5초는 끊긴다. 1.0초는 견딘다 |
| 값이 여럿일 때 **같은 이름을 여러 번** 보내기 | **마지막 값만 먹는다.** `cat_kewd=84&cat_kewd=87` 은 87 만이다. 콤마로 이어야 합집합(`84,87`) |
| 페이지 번호를 `recruitPage` 로 보내기 | **조용히 무시된다.** 1페이지가 계속 온다. 이름은 `page` 다 |
| 본문 태그를 그냥 걷어내기 | 숨긴 SEO 블록이 섞여 **화면에 글자가 0자인 공고에서 기술 61개**가 나온다 |
| 이미지 주소를 그대로 던지기 | 파일 이름에 공백·한글이 든다. `InvalidURL` 이 나고, 예외 목록에 없으면 수집 전체가 죽는다 |

## 그림 본문은 주소만 남긴다

본문이 그림 한 장인 공고가 **84 / 380건**이다. 수집 중에 그림을 읽으면 장당 40초라
**첫 실행이 4시간**이 된다 — 주기로 도는 파이프라인에 쓸 수 없다.

그래서 **수집은 그림을 읽지 않는다.** `기술스택` 칸에 주소만 남긴다.

```
(주)○○ | 기술스택: Java, Spring, https://pds.saramin.co.kr/.../recruit.png
```

`http` 로 시작하니 기술 이름과 섞이지 않는다. 주소는 퍼센트 인코딩해 둔다 —
회사가 올린 파일 이름에 공백과 한글이 든다.

**읽는 것은 수집이 끝난 뒤 도는 별도 단계의 일이다** (D-13). 합본(`csv/merged.csv`)을
읽어 `csv/merged_read.csv` 를 낸다 — 원본을 그대로 두므로 두 파일을 견주면 무엇이
채워졌는지 알 수 있다.

## 종료 코드

오케스트레이터가 읽는 값이다. 실패한 실행이 성공으로 기록되면 안 된다.

| 코드 | 뜻 |
|---|---|
| `0` | 정상. 조건에 맞는 공고가 없는 것도 여기다 |
| `1` | 설정 오류 — `.env` 항목이 없거나 근무지 이름을 못 옮겼다 |
| `2` | 차단. **여기까지 모은 것은 저장한 뒤** 이 코드로 끝낸다 |
| `3` | 이미 돌고 있다 (실행 잠금) |
