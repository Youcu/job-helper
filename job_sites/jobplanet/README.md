# 잡플래닛 수집기

```bash
../../.venv/bin/python3 jobplanet.py
```

`../../.env` 의 조건으로 **잡플래닛 자체 공고만** 수집해 `csv/jobplanet_post.csv` 를 만든다.
`.env` 는 저장소에 없다 — 민감 정보를 막으려고 있는 파일이라 예시 파일도 두지 않는다.
아래 표를 보고 직접 만들어야 한다.

## 왜 자체 공고만 긁는가

**이 사이트 개발 공고의 97%는 잡코리아 공고를 그대로 걸어 둔 것**이고, 그 97%에는
본문이 아예 없다. 백엔드 개발 500건 표본에서 유형별로 상세를 열어 셌다.

| `posting_apply_type` | 건수 | 지원자격 | 우대사항 | 담당업무 | 기술스택 |
|---|---|---|---|---|---|
| `jobkorea_inlink` | 413 (83%) | 0% | 0% | 0% | 0% |
| `jobkorea_outlink` | 68 (14%) | 0% | 0% | 0% | 0% |
| **`jobplanet`** | 11 (2%) | **100%** | **91%** | **100%** | **100%** |
| **`outlink`** | 8 (2%) | **100%** | **100%** | **100%** | **100%** |

0% 와 100% 로 완벽하게 갈린다. 중계 공고에는 `jobkorea_posting_id` 가 그대로 들어 있어서,
그 내용은 **잡코리아 수집기가 이미 가져온다.** 껍데기를 또 파도 얻을 것이 없다.

대신 남는 3%는 좋다 — 기술스택이 `["java","kotlin","spring boot"]` 처럼 **구조화된 배열**로
와서 산문 매칭이 필요 없고, **그림 본문이 0%**다 (사람인 18% · 잡코리아 24%).

## `.env` 에 적을 것

| 이름 | 필수 | 뜻 | 예 |
|---|---|---|---|
| `JOBPLANET_JOB_IDS` | **예** | 직무 **중분류** 코드. 콤마 구분 | `11904,11905` |
| `YOE` | 아니오 | 년차. 신입=`0`, N년차=`N`, 전체=`-1` | `0` |
| `HOME_LOCATIONS` | 아니오 | 근무지 이름. 비우면 전국 | `서울,성남시` |
| `EMPLOYMENT_TYPES` | 아니오 | 고용형태. 기본 `regular` | `regular` |
| `EDUCATION` | 아니오 | **여기서는 안 걸린다** (아래) | `대졸4` |
| `TECH_STACKS` | 아니오 | 보유 스택. **아직 거르지 않는다** | `Python,Django` |
| `HOPE_ANNUAL_SALARY` | 아니오 | 희망 연봉. **아직 거르지 않는다** | `3300` |

**접두사 없는 `JOB_IDS` 로 물러서지 않는다.** 물러서면 남의 사이트 코드로 잡플래닛을
긁게 되고, 숫자가 우연히 겹치면 엉뚱한 직무를 조용히 긁는다.

## 같은 `.env` 항목이 여기서는 다르게 쓰인다

셋 다 실측으로 정했고, **실행할 때 화면에 이유를 찍는다** — 조용히 무시하면 다른
사이트와 결과가 어긋난 이유를 나중에 못 찾는다.

### `EDUCATION` — 안 건다

자체 공고 대부분이 `학력무관`(코드 9)으로 등록돼 있다. 걸면 사라진다.

```
백엔드 개발 · 서울+경기 · 정규직 기준
  학력 조건 없음          자체 공고 37건
  + 대학교졸업(4년)       자체 공고  6건   ← 31건(84%)이 사라진다
  + 대졸4 · 학력무관       자체 공고 35건
```

### `EMPLOYMENT_TYPES` — 정규직·계약직만

잡플래닛 고용형태 코드는 **둘뿐**이다. `intern` 을 적으면 못 걸었다고 알리고 넘어간다 —
멀쩡한 값이라 멈추지는 않지만, 무엇을 못 걸었는지는 화면에 남는다. 오타(`정규직` 같은)는 멈춘다.

### `HOME_LOCATIONS` — 시도까지 걸고 나머지는 받은 뒤 거른다

잡플래닛 지역 코드에는 **구·시가 없다.** `서울=1` `경기=2` 수준이다.
`성남시` 를 적으면 `경기` 로 넓게 받은 뒤, 상세의 `location`(`"경기 성남시 분당구 …"`)으로
다시 거른다. 거르는 자리를 옮긴 것이지 조건을 버린 것이 아니다.

근무지가 빈 공고는 **통과시킨다.** 잘못 버리는 것보다 넘기는 쪽이 낫다 — 버린 공고는
있었다는 사실조차 안 남는다.

## 이 사이트의 함정

**전부 예외가 안 나고 결과도 나온다.** 그래서 코드가 막는다.

| 함정 | 실측 | 막는 자리 |
|---|---|---|
| 대분류와 중분류를 같이 보냄 | `level1=11600` 2,779 · `level2=11904` 579 · **둘 다 2,779** (중분류 무시) | `lib/filters.py` `occupation_value` |
| 같은 이름을 두 번 보냄 | `11904` 579 · `11905` 288 · `11904&11905` **288** · `11904,11905` 673 | `lib/client.py` `_query` |
| 경력을 값 하나로 보냄 | `years_of_experience=0` → **34,813(기준선 그대로)** · `0,0` → 22,508 | `lib/filters.py` `experience_range` |
| 1만 건 창 | `page × page_size > 10,000` 이면 공고도 **총계도 0** 으로 온다 | `lib/collect.py` |
| 마감일 표기가 둘 | 같은 `end_at` 인데 목록 `2026-09-06` · 상세 `2026.09.15` | `lib/record.py` |

사람인도 반복 파라미터에서 마지막 값을 썼고, 잡코리아는 첫 값이었다. 방향은 제각각인데
결과는 같다 — **조용히 값을 잃는다.**

## 차단 — Cloudflare, 그런데 게이트는 HTTP 버전이다

세 사이트 중 처음으로 봇 방어가 있다. 그런데 막는 것이 UA 가 아니다.

| 시도 | 결과 |
|---|---|
| UA 없이 / 정상 Chrome UA / HeadlessChrome UA | 403 |
| 브라우저 헤더 11개를 전부 맞춤 | 403 |
| Playwright (headless 실제 Chrome) | 403 |
| **`--http1.1` 하나만 추가** | **200** |

Cloudflare 가 **HTTP/2 지문**으로 거른다. `urllib` 은 기본이 HTTP/1.1 이라 추가 라이브러리
없이 통과한다 — 그래서 여기서 `requests` 를 쓰지 않는다.

**레이트리밋도 있다** (사람인·잡코리아에는 없었다). 0.3초로 던지다 맞았고, **1.2초로도
7요청 만에 맞았다** — 간격만이 아니라 **한동안 던진 총량**을 보는 듯하다. 그래서
`MIN_INTERVAL` 을 2.5초로 잡았다. 임계는 안 쟀다 — 재려면 일부러 막혀 봐야 하고,
막히면 한동안 못 긁는다.

403 이 오면 **재시도하지 않고 멈추되 거기까지 모은 것은 저장한다**(종료 코드 2).
**방금 돌린 뒤 곧바로 다시 돌리면 걸린다.** 몇 분 쉬었다 돌리면 풀린다.

## API

```
GET /api/v3/job/postings          목록. page + page_size, data.total_count
GET /api/v1/job/postings/{id}     상세. 본문 4칸과 skills
```

인증이 필요 없다. **총계가 목록 응답 안에** 들어 있어서 잡코리아처럼 따로 물어보지 않아도 된다.
코드표는 `/job` 페이지 HTML 의 RSC 페이로드 안 `display_filters` 에 통째로 들어 있다.

## 기술스택

①구조화 `skills` 배열 ∪ ②본문 산문 매칭. **`skills` 를 그대로 쓰면 안 된다** —
표기가 흔들리고(`MYSQL`·`java`) 기술이 아닌 것이 섞인다(`backend`, `slack`, `백엔드 개발`).
공통 코퍼스로 풀리는 것만 남기고, 못 푼 이름은 `_common/corpus_candidates.json` 에 쌓아
사람이 보게 한다. 코퍼스는 사람이 승인해야 는다 (D-14).

## 조건이 넓으면 아예 안 돌린다 (종료 코드 4)

이 사이트는 **한 번에 60요청쯤이 한계**다. 넘으면 중간에 403 이 나서 절반만 걷힌다.
그래서 목록을 훑어 **끝까지 걷을 수 있는지 먼저 재고, 못 걷겠으면 상세를 한 건도 받지
않고 물러난다.** 반쯤 든 CSV 는 "이 조건에 공고가 이만큼" 이라는 거짓을 만들고,
다음 실행에서 나머지가 채워진다는 보장도 없다.

```
필요한 요청 = 목록 페이지 수 + 자체 공고 수

  백엔드 · 신입 · 서울경기 · 정규직     목록 2 + 상세  5 =   7  → 돈다
  직무 6개 · 경력 전체                목록 13 + 상세 108 = 121  → 건너뛴다 (실측 58/108 만 걷혔다)
```

물러날 때 **CSV 를 건드리지 않는다.** 앞 실행 결과가 그대로 남는다.

### 오케스트레이터에서 쓰는 법

여러 사이트를 병렬로 돌릴 때, 종료 코드 4 는 **이 사이트만 건너뛰라는 신호**다.
실패(1·2)와 섞으면 안 된다 — 파이프라인 전체를 멈출 이유가 없다.

```bash
python3 jobplanet.py
case $? in
  0) ;;                                  # 정상
  4) echo "잡플래닛은 조건이 넓어 건너뜀" ;;   # 나머지 사이트는 계속 진행
  *) exit 1 ;;                           # 진짜 실패
esac
```
