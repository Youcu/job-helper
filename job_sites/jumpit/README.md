# 점핏 수집기

```bash
../../.venv/bin/python3 jumpit.py
```

`../../.env` 의 조건으로 공고를 전량 수집해 `csv/jumpit_post.csv` 를 만든다.
`.env` 는 저장소에 없다 — 민감 정보를 막으려고 있는 파일이라 예시 파일도 두지 않는다.
아래 표를 보고 직접 만들어야 한다.

## 지역·경력·직무만 거른다

**기술 필터가 공고 본문과 어긋난다.** `Spring Boot` 를 고르면 아무것도 안 나오는데, 그
필터를 풀고 공고를 열면 본문이 `Spring Framework` 를 요구한다. 사이트가 붙인 딱지와
회사가 실제로 쓰는 말이 다르다.

그래서 **기술로는 거르지 않고 받은 뒤 우리가 본문에서 읽는다.** 학력·고용형태는 필터
파라미터 자체가 없다. 무엇을 못 걸었는지는 실행할 때 화면에 찍는다 — 조용히 무시하면
다른 사이트와 결과가 어긋난 이유를 나중에 못 찾는다.

## `.env` 에 적을 것

| 이름 | 필수 | 뜻 | 예 |
|---|---|---|---|
| `JOB_ROLES` | **예** | 직무. **여섯 사이트가 함께 쓰는 이름**이다 | `백엔드,웹` |
| `YOE` | 아니오 | 년차. 신입=`0`, N년차=`N`, 전체=`-1` | `0` |
| `HOME_LOCATIONS` | 아니오 | 근무지 이름. 비우면 전국 | `서울,성남시` |
| `EMPLOYMENT_TYPES` | 아니오 | **여기서는 안 걸린다** (필터 없음) | `regular` |
| `EDUCATION` | 아니오 | **여기서는 안 걸린다** (필터 없음) | `대졸4` |
| `TECH_STACKS` | 아니오 | **일부러 안 건다** (위 참조) | `Python` |
| `HOPE_ANNUAL_SALARY` | 아니오 | 이 사이트는 **급여를 아예 안 준다** | `3300` |

**직무는 사이트 코드가 아니라 이름으로 적는다.** `.env` 는 여섯 사이트가 함께 쓰는
한 벌이라, `JOB_ROLES=백엔드,웹` 하나를 적으면 이 사이트가 `tags/jumpit_role_map.json` 로 자기 코드를 찾는다.
쓸 수 있는 이름은 `job_sites/_common/roles.json` 에 있고 별칭도 받는다 — `서버`·`Backend`
라고 적어도 `백엔드` 로 알아듣는다.

**한 이름이 코드 여럿으로 펼쳐진다.** 같은 일을 하는 공고를 사이트가 어떻게 쪼개 뒀든
다 걷는 것이 목적이다. 이 사이트에 없는 직무는 조용히 빠지지 않고 **못 걸었다고 화면에
찍는다** — 조용히 빠지면 왜 결과가 적은지 못 찾는다.

### 지역 코드는 **사람인 것과 같다**

같은 회사가 만든 사이트라 코드 체계가 같다. `saramin/tags/saramin_location.json` 에서
떴고 실측으로 확인했다 (`101000`=서울 401건 · `101010`=강남구 155건 · `102180`=성남시 118건).

**시 코드가 구를 포함한다.** 사람인은 포함하지 않아 `성남시` 를 구 셋으로 펼쳐야 했는데
여기는 반대다 — `102180` 단독 118건과 구 셋을 함께 보낸 118건이 같았다. 그래서 **펼치지
않는다.**

## 이 사이트가 앞선 셋과 반대로 도는 것

| | Wanted | 사람인 | 잡코리아 | 잡플래닛 | **점핏** |
|---|---|---|---|---|---|
| 같은 이름을 두 번 | — | 마지막 값 | 첫 값 | 마지막 값 | **둘 다 먹는다 (OR)** |
| 시 코드가 구를 포함 | — | 아니오 | 시 코드 없음 | 구 코드 없음 | **예** |
| 차단 | UA | 없음 | 없음 | HTTP/2 지문 | **없음** |
| 본문이 그림 | — | 18% | 24% | 0% | **0%** |

실측 — `jobCategory=1` 139건 · `=2` 73건 · `1&2` **189건** · `1,2` **189건**.
둘 다 OR 로 먹는다. 화면도 반복 파라미터로 보내므로 그대로 따른다.

## 함정 — 총계는 **중복을 포함한 수**다

한 공고가 여러 직무에 걸쳐 있으면(상세의 `jobCategories` 가 배열이다) 직무를 여럿 보낼 때
**같은 공고가 여러 번 실려 온다.**

```
직무  1개          총계 139 · 받음 139 · 고유 139 · 중복  0
직무  2개(1,3)     총계 153 · 받음 153 · 고유 152 · 중복  1
직무 21개(전체)     총계 698 · 받음 698 · 고유 694 · 중복  4
```

그래서 총계는 **받은 항목 수**와 견준다. 고유 수와 견주면 직무를 여럿 넣는 순간 늘
불일치가 나와 신호로 못 쓴다 — 진짜로 흘렸을 때를 못 알아챈다. 고유 수와 겹친 수는
화면에 따로 찍는다.

### 끝 너머에서 총계가 0 으로 온다

```
page=46  11건  totalCount 731  emptyPosition=false     ← 마지막 페이지
page=47   0건  totalCount **0**  emptyPosition=true
```

총계를 매번 덮어쓰면 마지막에 0 이 남아 "다 모았다" 는 판정이 무너진다. **첫 값만 믿는다.**

## API

```
GET /api/positions?jobCategory=N&career=N&locationTag=N&sort=popular&page=N&size=N
GET /api/position/{id}
```

`https://jumpit-api.saramin.co.kr` 이다. 인증도 쿠키도 필요 없고, UA·Referer 를 어떻게
보내도 200 이 온다 — 네 사이트 중 가장 순하다. 그래도 요청 사이에 간격을 둔다.
**레이트리밋을 못 봤다는 것이 없다는 뜻은 아니다** (잡플래닛에서 그렇게 넘겼다가 막혔다).

`career=N` 은 **N년차가 지원할 수 있는 공고**다 — `minCareer <= N <= maxCareer`.
표본 177건에서 이를 어기는 공고가 하나도 없었고, `career=0` 은 신입 공고와 정확히
겹쳤다(57/57 이 `newcomer=true`).

## 기술스택

①구조화 `techStacks` ∪ ②본문 매칭. **목록과 상세의 모양이 다르다.**

```
목록  "techStacks": ["Git", "Next.js", "React"]              문자열 배열
상세  "techStacks": [{"stack": "Git", "imagePath": "…"}, …]   객체 배열
```

하나만 가정하면 한쪽에서 조용히 빈 목록이 나온다. 둘을 합치고, 공통 코퍼스로 풀리는
것만 남긴다. 못 푼 이름은 `_common/corpus_candidates.json` 에 쌓아 사람이 보게 한다 (D-14).

**②가 특히 중요하다** — 딱지와 본문이 어긋나는 것이 이 사이트의 특징이라, `Spring Boot`
딱지가 없는 공고에서 본문의 `Spring Framework` 를 잡아내는 것이 ②의 일이다.
